# Godot boundary security review

Review owner: `review_security`. Scope: independent **source-only** review of the comparison bridge, native hosts, renderer message handling, and lifecycle. No security tests, network probes, or runtime acceptance checks are executed by this reviewer. Checked against source available on 2026-09-10. All eight tracked findings below have owner corrections verified in source. This is not native/runtime acceptance or a shipping multiplayer-integration approval.

## Trust and ownership

The Kotlin game/session authority remains the owner of player identity, legal actions, hidden state, and randomness. Both Godot presentations may receive the same explicit recipient projection: the viewer's hand, public opponent counts, public turn/claim information, and challenged-card evidence. Authoritative `GameState`, other hands, undealt/discarded cards, future penalty outcomes, admission credentials, reconnect credentials, and network connection handles do not belong in renderer messages or logs.

Renderer input is a request to the existing authority. The native owner binds the actor and current presentation; the renderer must not choose an actor, certify an outcome, change the revision, or nominate arbitrary resources/code to execute. The comparison's local authority and fixture behavior must remain distinguishable from a shipping multiplayer integration.

`EnginePayload` bounds a document but does not prove that it is a safe game projection. `EngineEventGate` checks presentation/protocol identity, accepted sequence order, readiness, and closure; it does not validate game schema, exact current revision, card ownership, or foreground state. Those checks must be provided by the new game adapter and native lifetime owner. A fresh presentation needs a fresh identifier and gate, and queued callbacks must retain their original lifetime identity.

## Research that affects implementation

1. **Godot JSON parsing needs a strict boundary in front of it.** The pinned engine documentation explicitly permits trailing commas, raw newlines/tabs in strings, lax number parsing, and cleanup of some invalid Unicode [G1]. Its implementation parses numeric tokens into `double` and assigns object members with `object[key] = v`, replacing equal decoded keys [G2]. Checking a parsed dictionary cannot recover duplicates or malformed source spellings. Reject malformed UTF-8/Unicode, excessive bytes/depth, duplicate decoded keys, unknown fields, and invalid variants before the permissive parser loses that information. Then enforce collection and value bounds.
2. **Revisions and sequences must remain exact.** Use canonical nonnegative decimal strings through the JSON/native boundary, validate the entire string and signed-`Long` range, and compare numerically without converting through floating point. Godot JSON numbers cannot represent the full Kotlin `Long` range exactly [G1, G2]. Booleans, fractions, signs, whitespace, leading zeroes, exponents, and overflows are not canonical counter strings.
3. **Native plugin callbacks have specific thread ownership.** At 4.7.2, `GodotPlugin` setup, main-loop-start, and termination callbacks are documented on the render thread. `emitSignal` itself queues `nativeEmitSignal` through `runOnRenderThread` [G3]. `Godot.runOnRenderThread` requires a started render thread and forwards through a nullable render view [G4]. Startup retention, queue bounds, native owner dispatch, and final lifetime checks therefore need explicit handling; calling a dispatch helper alone is not proof that a message was delivered to the current presentation.
4. **Android process choice affects teardown.** The official embedding guide supports one engine instance per process and warns about configuration/resizing limitations [G5]. Android assigns component processes through `android:process` [G6]. A separate renderer process can protect the shell's lifetime from engine termination; it is not, by itself, an independent credential sandbox. Keep renderer component entry points nonexported unless a separately authenticated entry contract is intended. Check the actual manifest and IPC rather than inferring process separation from class names.
5. **Apple embedding touches global engine and UIKit state.** Pinned Apple source exposes a class-wide `GDTAppDelegateService.viewController`, changes root-controller method implementations, and drains the main run loop inside `GDTView.drawView` [G7]. Teardown can therefore be reentrant even on the main thread. A probe needs one-shot engine ownership, draw/cleanup exclusion, fixed resource ownership, and explicit handling of the root-controller hook. The desktop LibGodot header is not evidence of a qualified iOS host surface [G8]. No shipping iOS factory or repeated-entry claim follows from a standalone export or this source review.
6. **Android's diagnostic parser also needs strict preflight.** Android 16 `JSONTokener` explicitly accepts comments, single-quoted/unquoted strings, alternate separators, and non-JSON numeric forms. Its object reader overwrites duplicate keys, recursively reads arrays/objects without a depth parameter, and the `JSONObject(String)` constructor does not require end-of-input [G10]. A scanner that only recognizes double-quoted JSON cannot safely bound that parser's nesting: quotes inside accepted comments can hide actual brackets from the scanner. Byte limits alone do not provide a recursion limit.
7. **The internal Apple bootstrap has argument-size assumptions.** `change_to_launch_dir` indexes a fixed 512-byte buffer using the directory prefix found in `argv[0]`; the argument-copy path has 64 slots and appends `Info.plist` arguments without a capacity parameter [G11]. The iOS owner identified this constraint. The runtime now requires the actual absolute bundle executable path below 512 UTF-8 bytes, supplies a small fixed argument list, and rejects `godot_cmdline` injection. Those guards were independently compared with the pinned source.

## Review record

The common codec now preflights the whole document before JSON object construction, bounds native documents at 65,536 UTF-8 bytes and renderer events at 4,096 bytes, limits nesting to 16 and values to 4,096, and rejects duplicate decoded keys and malformed Unicode. `ViewJsonShape` requires the complete nested view schema and raw primitive types before DTO decoding. This is necessary because default values on serializable properties make those fields optional [G9]. The renderer scanner has matching depth/value ceilings and retains fractional/exponent field spellings long enough to reject them for integer fields before Godot converts numbers to floating point.

The adapter holds one fixed recipient, requires strictly newer view revisions, and compares intent revision to the current accepted view before checking foreground state, native action controls, own-hand membership, and available actions. It constructs the actor-bearing `GameAction` itself. Its qualification driver holds authoritative state privately, obtains outbound views only through `LastLightEngine.viewFor`, and lets opponent policy read only the opponent's own projection. Its explicit `refreshView` advances the presentation revision without changing domain state, allowing rejected-submission reconciliation.

Renderer source conceals ranks in the presentation-state copy, clears reveal and selection on new views and foreground loss, and clears all game data on closure. Resource paths are chosen from the fixed 2D/3D presentation allowlist. The shared renderer does not log raw views or intents; standalone logging contains only the generated event type. Input, pause, privacy-cover timing, and rendered pixels still require separate runtime evidence.

Both presentation implementations have now been inspected. The 2D table erases private textures, captions, accessibility names, tooltips, and card bindings before detaching hand nodes. The 3D table rebuilds hand meshes and labels from the concealed projection, detaches old nodes, and clears its binding array; opponents receive only count-derived representations and public challenge evidence. The shared root detaches the presentation on closure and stops feedback. Resource textures represent generic ranks, not authoritative hidden state.

Android's native Activity owns the local qualification authority on the main thread and binds a newly generated presentation ID. Normal practice uses `SecureRandom`; seed 2 is an explicit comparison-fixture choice. The engine Activity is nonexported in `:godot`; the chooser does not initialize the engine and withholds launch while that process remains visible. A one-shot process claim rejects Activity restoration or reuse. Native concealment hides the surface's accessibility descendants. Uncovering requires delivery of the current foreground command, two subsequent supported GL draw callbacks [G3], and matching native foreground epoch/readiness at the final main-thread callback. Close invalidates that epoch, authority, and the plugin, replaces waiting commands with terminal Close, and uses a 250 ms fallback if the renderer cannot acknowledge. Pinned upstream destruction requests a 1,500 ms timed render-exit wait [G4], whose early-return and monitor limitations are described in the Android follow-up below; final process termination is confined to the verified `:godot` process. Draw callbacks do not prove buffer presentation, and neither queue acknowledgment nor `finish()` alone proves process exit.

The Android plugin bounds incoming work at 32 entries and outgoing work at 16, counts the active delivery against capacity, and retains at most one upstream signal in flight. Posted callbacks check lifetime closure before dispatch. Native diagnostics require the requested ID, increasing canonical sequence, current view revision, matching presentation/mode, bounded geometry, and a fixed field/group allowlist. Their final `rect`/`clipRect` schema matches the renderer; both arrays receive finite-coordinate and nonnegative-size validation. They do not alter authority or decide privacy-cover visibility. `EvidenceRecorder` keeps one replaceable pending snapshot plus the active write, writes through `AtomicFile` into app-private storage, and logs only fixed messages. Evidence contains public counts/status, geometry, fixed enums, and counters, not card IDs/ranks or arbitrary renderer strings. The added display-density value is numeric, finite, and bounded at both native and renderer entry; invalid density fails the bound launch before Ready or scene creation with a fixed diagnostic message.

The iOS runtime now performs real source-coupled bootstrap, checked `Main::setup2`, `Main::start`, iteration, and cleanup. It owns one bootstrap attempt per process, gates methods to the main thread, bounds command/event queues, and delays cleanup until draw/engine/native-delivery depths are zero. An early bootstrap/setup failure quarantines the stopped instance instead of guessing that normal cleanup is safe. Its C++ preflight bounds depth and values and handles decoded duplicate keys and Unicode before Foundation parsing. Foreground loss and close synchronously install a native opaque cover and hide engine accessibility elements; a resumed cover is removed only after concealment delivery and a subsequent completed draw. Each queued intent carries its native foreground generation, which is checked with current foreground/revision immediately before delivery. Cleanup clears queued documents, handlers, and the launch document; normal cleanup also releases the view/controller and global runtime lookup. Native pixels and release behavior still need execution evidence.

The SwiftUI wrapper, bundled diagnostic scene, and source `Info.plist` have also been inspected. The wrapper chooses bundled resources for the diagnostic or explicit 2D/3D fixtures, owns application lifecycle, and closes the runtime when dismantled. The native runtime validates envelopes and action shape; complete game semantics and actor authorization remain duties of the common authority. The current iOS executable observes fixture events without connecting a gameplay authority through `eventHandler`, so it does not establish a Last Light practice loop, a shipping KMP factory, or safe repeat initialization. Its one-shot/quarantine limits are intentional and must remain visible in qualification reporting.

## Follow-up: early iOS bootstrap rejection

After CI run [34428221586](https://github.com/Apdelrahman1911/PartyDeck/actions/runs/34428221586), this reviewer inspected the existing failure attachment `28F67620-E355-4777-A8DF-A90044A3F7D7.json` and the app stderr extracted by the CI owner. No native execution was performed by this reviewer. The attachment shows one bootstrap attempt, no Ready/draw/iteration, a quarantined OS singleton, and restored idle-timer policy. The stderr identifies the failure directly at `Main::setup`: `--path` was rejected because path overrides were not compiled in.

This exposed a missed compile-option requirement in the host configuration. Pinned `SConstruct` defaults `disable_path_overrides` to true for export templates and defines `OVERRIDE_PATH_ENABLED` only for editor builds or an explicit false value [G22]. The probe built `target=template_debug` without changing that default, while its owned argument list always supplied `--path`. Pinned `Main::setup` rejects that argument before loading project settings; iOS `--main-pack` has the same requirement [G19]. Its error label performs partial core teardown and returns an error, which `apple_embedded_main` maps to `EXIT_FAILURE` while leaving the OS allocated [G7, G19]. The observed OS singleton therefore does not justify calling full cleanup or bypassing quarantine.

The other requested bootstrap checks found no additional source mismatch: `process_args` consumes the explicit argument count and supplies the terminating null itself; the host constructs all string storage before taking pointers and remains within the checked argument/path limits [G11]. The wrapper selects its diagnostic project or optional pack from bundled resources and does not forward application arguments or renderer-selected paths. With path overrides enabled, `--path` checks and changes the working directory before project settings are loaded; the current plist supplies no competing `godot_path`, and this host requests no remote filesystem [G14, G19, G22]. The requested `gl_compatibility`/`opengl3` pair is explicitly accepted by the pinned GLES3 configuration [G13, G19]. These source checks do not establish that subsequent native graphics setup will succeed.

The iOS owner's correction now supplies the supported `disable_path_overrides=no` option and fails compilation when `OVERRIDE_PATH_ENABLED` is absent. The runtime records the actual bootstrap, setup2, and main-start return values, initialized to `-1` for unattempted stages; it preserves the existing success predicates and terminal paths. Existing XCTest helpers retain coarse failure measurements and still fail/throw when their conditions are not met. Those changes were independently reviewed in source. The original metrics alone could not distinguish an unattempted setup2 stage from a failed one; the added return observations address that ambiguity, while app stderr remains necessary because the Apple bootstrap collapses `Main::setup` errors to an exit status. A successful native rerun remains required; no implementation was edited and no tests/probes were run for this diagnosis.

## Follow-up: Android native method lookup and render-thread exit

The Android startup failure was independently traced in the pinned 4.7.2 source. `@UsedByGodot` registration stores Java methods in `JNISingleton.method_map`, while ordinary `Object.has_method` searches script/ClassDB methods. `JNISingleton.callp` dispatches ordinary Object methods first, then its Java registry; its bound `has_java_method` API checks that registry [G23]. Thus the previous `has_method("get_display_scale")` guard could reject a callable bridge method, and the diagnostics guard had the same defect. Java `double` maps to `Variant::FLOAT`; changing the Kotlin return signature is not required. User signals have separate ordinary signal registration and are unaffected.

The inspected renderer correction introduces `_plugin_has_method`, checks ordinary methods first, and otherwise queries `has_java_method` only when that API is bound. Both density and diagnostics use it. The regular iOS ClassDB path remains valid, and density still requires a finite number in `0.5..8.0`. Missing or invalid Android density still fails before Ready or presentation creation. The frozen `main.gd` SHA-256 was independently read as `2a9798e54e31b98b992eb0abf4f282dcdadccc22f9a79d14066aacb706c6e9e5`. The accompanying 3D scroll-callback correction rechecks tree membership after each frame await before using the tree or controls, preserving layout identity/validity and current hand-visibility checks. Its frozen `presentations/three_d/table.gd` hash was `924617ff3d08e00df38bb6c33ed7e869f636e23e5022d676557edf4141b4f83c`. No additional source blocker was found in these narrow corrections; native rerun evidence remains separate.

The reported teardown warning also has a concrete source hazard. The OpenGL render thread's timed exit function performs a single monitor wait and immediately returns `mExited`. EGL cleanup notifies the same monitor before the outer thread-finalization path sets `mExited`, so a false return may precede the requested timeout [G24]. This supports an early-wake diagnosis but does not independently establish the cause of any particular native run. Native engine destruction occurs inside render-thread exit, before EGL cleanup; its termination and force-quit callbacks may therefore already have fired before an exit-wait retry finishes.

The frozen host mitigation was independently reviewed in `GodotGameActivity.kt`, `RendererExitWait.kt`, its three test bodies, and the Android host README. Privacy/authority/plugin closure still precedes teardown on the main thread. The helper retries only positive remaining waits against one monotonic 1,500 ms budget, stops on interruption, and reports success only when the public renderer-exit API returns true. Unconfirmed exit records a fixed failure without replacing an earlier cause, then retains the original upstream destruction/final process cleanup. The existing plugin termination observation covers callbacks that precede registration of the optional `destroyAndKillProcess` Runnable. PartyDeck's plugin destroy hook only repeats the disposal already done before preflight, so no additional callback-order defect was found in this fixed plugin set. A monotonic retry budget cannot guarantee a hard wall-clock bound while native cleanup holds the monitor, and surface detach has a separate untimed exit wait. The owner README preserves these limits and states that termination callbacks alone do not prove graceful cleanup. No additional source blocker was found in this mitigation; native exit and process absence still require runtime evidence. No tests, probes, implementation changes, or Git commands were used for this follow-up.

## Architectural follow-up: one dormant iOS engine

**Source assessment: feasible to prototype with a separate presentation-lifetime contract.** This does not qualify the current one-shot implementation for re-entry. The exact upstream checkout was confirmed at `ed1daf0bf001b61586d9930840f2f1394092c079` with no tracked source changes. No bootstrap or cleanup needs to repeat merely to replace a scene: `SceneTree::unload_current_scene()` synchronously deletes the current scene on the main thread while preserving the root and engine [G12]. The existing `PDGodotRuntime.close()` instead performs full cleanup and must remain terminal. The initial one-shot native test handoff can proceed independently of this future design.

The concrete constraints are:

- **Retain the native surface with the engine.** The display server obtains the view and rendering layer through the global `GDTAppDelegateService.viewController`; graphics initialization uses that layer [G13]. Retain one stable controller/view/layer, detach it from navigation while idle, and keep its root-policy override. Replacing or releasing the surface while retaining the initialized graphics driver is not established by these sources. Keep the project/settings/pack fixed and select scenes through the known allowlist.
- **Stopping frames does not stop every service.** `GDTView.stopRendering` invalidates its display link/timer and clears touch slots. Its motion manager starts updates in `godot_commonInit` and stops them only in `dealloc`; the public view header exposes no sensor-suspension method [G7]. The iOS owner independently identified the same gap. A retained view therefore needs an explicit, source-coupled sensor-control hook or maintained patch. `OS_AppleEmbedded::on_enter_background` pauses camera handling and calls focus-out, which stops the view and calls the CoreAudio member's stop method [G14].
- **Audio suspension needs evidence for the selected driver.** `AudioDriverCoreAudio::stop()` returns no result, logs `AudioOutputUnitStop` failure, and clears its private `active` flag only on success; there is no public active getter [G15]. A host-side `audioStopped = true` after focus-out would not establish suspension. Future qualification needs actual AudioUnit/callback observation or an audited narrow diagnostic hook. The audio manager can also fall back to `AudioDriverDummy`, whose default thread can continue processing audio while focus-out stops the separate CoreAudio member [G14, G18]. Constrain the supported driver or implement and qualify that driver's dormant path. Native audio-session/interruption handling must respect presentation activity; the upstream export delegate's interruption-ended handler calls focus-in, which could restart audio outside a game [G13, G14].
- **Scene removal is not a global queue/resource purge.** `unload_current_scene` removes only `current_scene`. Pending scene changes, tree-owned timers/tweens, deferred calls, and queued deletion have separate lifetimes [G12]. In particular, `change_scene_to_node` stages a replacement for a later process pass, and a node-bound tween is retired on a later step after its owner disappears [G16]. Freezing iteration immediately after `queue_free()` can retain old objects and captured data. Recipient data must never live in persistent autoloads, script static variables, or shared asset resources; generic fonts/textures may remain resident. `ResourceCache::clear()` only clears registrations and is not a recipient-data erasure API [G16].
- **Input and native callbacks outlive visible nodes unless gated.** `Input::flush_buffered_events()` dispatches buffered events; it does not discard them [G17]. Close the old authority/presentation gates before draining input, keep the next scene absent during that drain, and suppress touch, hardware-key, keyboard, and other input producers while dormant. Native callbacks and queue entries need the presentation ID and captured native lifetime generation; they must not look up a newly installed recipient/handler when an old callback finally runs.
- **Dormancy retains engine memory and global state.** It cannot promise a zero engine footprint or secure heap/GPU-memory erasure. An old surface buffer also survives merely stopping rendering. Keep the native cover throughout teardown and reattachment, clear recipient bindings and render a neutral frame before settling idle, then require a fresh concealed frame before uncovering a new entry. If a failure or memory-pressure policy requires full engine cleanup, that cleanup is terminal for the process; later initialization remains unqualified.

A viable native contract would separate the app-owned engine from a disposable presentation handle:

1. **Open:** allow one presentation at a time, only after the previous teardown completed. KMP creates a new random presentation ID, fixed-recipient adapter, event gate, revision/sequence state, and native generation. Attach the retained surface under a cover, instantiate a fresh whole renderer/controller scene, and deliver only the new recipient projection. The current controller's `_closed`/`_launched` states remain terminal; do not reset an old controller. Enable input/uncover only after this presentation's Ready and completed concealed draw.
2. **Leave:** KMP synchronously closes the old handle and advances the native generation. Cover the surface and hide accessibility, invalidate queues/diagnostic requests/handler closures, and reject every later old-ID or old-generation intent. At a main-thread boundary with no draw/engine/delivery stack active, stop feedback, clear launch/view/selection/private bindings, cancel scoped timers/tweens/tasks, unload the game scene, and complete bounded deferred/input/render cleanup while still covered. Only then detach the surface and report dormant. Do not call `SceneTree.quit`, `Main::cleanup`, or `apple_embedded_finish` on this path.
3. **Dormant:** keep no recipient projection, native presentation handler, game-scene controller, or pending presentation work reachable from the retained runtime. The engine/view may remain allocated, but rendering, audio, sensors, and input must be suspended. Forward application foreground or audio-interruption recovery to Godot only when a current presentation also permits it. Native navigation remains KMP-owned.
4. **Failure:** if scoped teardown or service suspension cannot complete, keep the cover and old gate closed, quarantine the engine, and refuse another Godot entry in that process. Do not silently reinterpret a partial teardown as dormant.

This is a source-backed candidate contract, not an implementation or production claim. Repeated entry across different recipients, old callback rejection, absence of private bindings, stopped services, native surface reattachment, and memory/resource behavior still require a separate executable qualification. No tests/probes or implementation changes were made for this follow-up.
